# VINFREY : AiRi

**AiRi** คือ AI คู่สนทนาส่วนตัวที่คุยด้วยน้ำเสียงแบบเพื่อนสนิท จำเรื่องที่ผู้ใช้อยากให้จำได้ในเครื่อง
และส่งงานที่ซับซ้อนต่อให้ทีม AI หลายตัว (Multi-agent Workflow) ช่วยวางแผน เขียน และตรวจงานให้
โดยการลบ Memory และการบันทึกเรื่องที่ AI เสนอให้จำ ต้องได้รับการอนุมัติจากผู้ใช้ก่อนเสมอ

**VINFREY** คือชื่อของระบบ ส่วน **AiRi** คือตัวตนที่ผู้ใช้คุยด้วย
ใช้งานได้ทั้งผ่านหน้าเว็บในเครื่อง (Streamlit Web UI) และผ่าน Command Line
ฟีเจอร์ที่เป็น AI ใช้ OpenAI API จึงต้องมี API Key และอินเทอร์เน็ต

---

## ฟีเจอร์หลัก

### 💬 คุยกับ AiRi (Persona)
AiRi คุยแบบเพื่อนที่สุขุม ตรงไปตรงมา และอบอุ่น มีมุมมองของตัวเอง
กล้าแย้งอย่างมีเหตุผลแทนที่จะเห็นด้วยทุกเรื่อง และไม่ประจบหรือแต่งเรื่องว่าจำอะไรได้ทั้งที่ไม่มีข้อมูล

**ผู้ใช้ได้อะไร:** ได้คู่คิดที่ช่วยมองอีกมุม ไม่ใช่แค่ผู้ช่วยที่ตอบตามสั่ง
และเมื่อสั่งงานจริงจัง AiRi จะเปลี่ยนเป็นโหมดโฟกัสโดยยังคงน้ำเสียงเดิม

### 🧠 Memory ส่วนตัวในเครื่อง
ผู้ใช้สั่งให้จำได้ด้วย `/remember` และดูทั้งหมดได้ด้วย `/memories`
เมื่อคุยกันครั้งต่อไป AiRi จะหยิบเรื่องที่เกี่ยวข้องมาใช้ประกอบคำตอบ
ข้อมูลเก็บเป็นไฟล์ SQLite ในเครื่อง และ AiRi **ไม่บันทึกอะไรเองโดยอัตโนมัติ**

**ผู้ใช้ได้อะไร:** AiRi จำสิ่งที่ผู้ใช้เลือกให้จำเท่านั้น และผู้ใช้ควบคุมได้ว่าจะเก็บหรือลบอะไร

> Memory ที่เกี่ยวข้องกับข้อความจะถูกส่งไปกับคำขอถึง OpenAI ด้วย เพื่อใช้เป็นบริบทของคำตอบ

### ✅ ApprovalGate: อนุมัติก่อนลบ หรือก่อนบันทึกสิ่งที่ AI เสนอ
เมื่อสั่งลบ Memory ด้วย `/forget` หรือเมื่อ AiRi เสนอเรื่องที่ควรจำ รายการนั้นจะรอให้ผู้ใช้อนุมัติก่อน
ผู้ใช้กดปุ่ม **อนุมัติ** / **ปฏิเสธ** ในหน้าเว็บ หรือพิมพ์ `/approve`, `/deny` เองได้
แต่ละรายการทำงานได้เพียงครั้งเดียว และก่อนลบระบบจะตรวจซ้ำว่ายังเป็น Memory รายการเดิมอยู่
หมายเหตุ: `/remember` เป็นคำสั่งที่ผู้ใช้พิมพ์เอง จึงบันทึกทันทีโดยไม่ต้องผ่านขั้นอนุมัติ

**ผู้ใช้ได้อะไร:** AI ไม่สามารถลบหรือบันทึก Memory เองได้
แม้ AI จะพิมพ์คำว่า "/approve" ออกมา ข้อความนั้นก็เป็นแค่ข้อความ ไม่ใช่การอนุมัติจริง
รายการที่รออนุมัติแยกกันในแต่ละ Session และจะถูกล้างเมื่อเริ่มบทสนทนาใหม่

### 🛠️ Multi-agent Workflow (`/work`)
ส่งงานด้วย `/work <งาน>` แล้ว AI สี่บทบาทจะทำงานต่อกันเป็นลำดับ

| บทบาท | หน้าที่ |
| --- | --- |
| Planner | วางแผนงานเป็นขั้นตอน |
| Researcher | รวบรวมข้อมูลพื้นหลัง ข้อจำกัด และข้อสมมติ |
| Builder | สร้างผลงาน และแก้ไขตามคำติชม |
| Reviewer | ตรวจผลงานเทียบกับโจทย์ แล้วตัดสิน PASS หรือ FAIL พร้อมเหตุผล |

ถ้า Reviewer ให้ FAIL งานจะถูกส่งกลับไปแก้ได้สูงสุด 3 รอบ
หน้าเว็บแสดงความคืบหน้าทีละขั้น ผลลัพธ์สุดท้าย และรายละเอียดของแต่ละ Agent

**ผู้ใช้ได้อะไร:** ได้งานเขียนหรือโค้ดที่ผ่านการวางแผนและตรวจทานมาแล้ว และเห็นว่าแต่ละขั้นคิดอะไร
(PASS จาก Reviewer ยังเป็นการตัดสินของ AI จึงควรตรวจงานสำคัญด้วยตัวเองเสมอ
และโค้ดที่ได้จะถูกแสดงเป็นข้อความเท่านั้น ระบบไม่สั่งรันให้)

### 🧮 Tool Calling
ระหว่างแชต AiRi เรียกใช้เครื่องมือคำนวณได้สองตัว

- **calculate** — คำนวณเลขคณิต เช่น บวก ลบ คูณ หาร ยกกำลัง
- **date_math** — นับจำนวนวันระหว่างสองวันที่ หรือบวกลบจำนวนวันจากวันที่หนึ่ง

เครื่องมือทั้งสองคำนวณในเครื่องเท่านั้น ไม่อ่านไฟล์ ไม่เชื่อมต่ออินเทอร์เน็ต และไม่แตะ Memory

**ผู้ใช้ได้อะไร:** ได้คำตอบตัวเลขและวันที่ที่แม่นยำจากการคำนวณจริง ไม่ใช่การเดาของ AI

## ฟีเจอร์เสริม

### 💡 AiRi เสนอสิ่งที่ควรจำ (`/suggest`)
AiRi อ่านข้อความล่าสุดที่ผู้ใช้พิมพ์ แล้วเสนอเรื่องที่น่าจำได้ไม่เกิน 3 ข้อ พร้อมเหตุผล
ทุกข้อเสนอต้องผ่าน ApprovalGate ก่อนบันทึก และข้อความที่ดูเหมือนรหัสผ่านหรือ API Key
ตามรูปแบบที่ระบบรู้จักจะถูกคัดออกก่อนส่งให้ AI

### 🗓️ รู้วันเวลาและงานล่าสุด (Context Awareness)
ทุกข้อความแชตจะบอก AiRi ถึงวันที่และเวลาปัจจุบัน จึงตอบคำถามอย่าง "อีกกี่วันถึงวันหยุด" ได้
หลังจบ `/work` แชตครั้งถัดไปจะได้สรุปสั้น ๆ ของงานล่าสุด เพื่อให้ถามต่อเกี่ยวกับงานนั้นได้
สรุปนี้ถูกจำกัดความยาว และมีการกรองโค้ด ข้อความที่ดูเหมือนรหัสลับ และ path ส่วนตัวออกก่อน
(การกรองครอบคลุมรูปแบบที่พบบ่อย ไม่ได้รับประกันทุกกรณี)

### 📊 ดูการใช้งาน API (`/usage`)
แสดงจำนวนครั้งที่เรียก API และจำนวน Token ที่ใช้ใน Session นี้ ทั้งในแชตและแถบด้านข้างของหน้าเว็บ
แต่ละ Session มีเพดาน 40 ครั้ง และระบบจะตรวจล่วงหน้าว่าโควตาพอสำหรับงานที่กำลังจะเริ่ม
ถ้าไม่พอจะปฏิเสธก่อนส่งคำขอ

> เพดานนี้เป็นตัวกันการใช้งานเกินต่อ Session ไม่ใช่เพดานค่าใช้จ่ายของบัญชี
> เปิดหน้าเว็บใหม่หรือรันโปรแกรมใหม่จะเริ่มนับใหม่ ควรตั้ง Budget ในบัญชี OpenAI ด้วย

### 🎬 Live Demo Mode
โหมดสำหรับนำเสนอ เปิดด้วยการตั้งค่า `VINFREY_DEMO=1`

- ใช้ Memory ชั่วคราวแยกต่อ Session และไม่แตะ Memory จริงของผู้ใช้
  (CLI ลบทิ้งเมื่อออกจากโปรแกรม ส่วนหน้าเว็บลบเมื่อ Session ถูกเก็บกวาดหรือปิด Server ตามปกติ
  ซึ่งอาจไม่ใช่ทันทีที่ปิดแท็บ)
- ไม่โหลดโปรไฟล์ส่วนตัว จึงไม่ส่งชื่อจริงไปกับคำขอ
- จำกัดไว้ที่ 20 ครั้งต่อ Session และมีป้าย **LIVE API DEMO** แจ้งชัดเจน

> โหมดนี้ยังเรียก OpenAI API จริง จึงต้องมีอินเทอร์เน็ต API Key และอาจมีค่าใช้จ่าย
> ไม่ใช่โหมดออฟไลน์ และไม่ใช่ AI ที่รันในเครื่อง

### 🙋 โปรไฟล์ส่วนตัว (ไม่บังคับ)
ใส่ชื่อเล่นไว้ในไฟล์โปรไฟล์ในเครื่องได้ AiRi จะเรียกชื่ออย่างเป็นธรรมชาติ
ถ้าไม่ได้ตั้งไว้ AiRi จะไม่เดาชื่อผู้ใช้

### 🖥️ ใช้ได้ทั้งหน้าเว็บและ Command Line
- **Web UI (Streamlit):** เปิดในเครื่องที่ `127.0.0.1` มีปุ่มอนุมัติ แสดงสถานะการทำงาน และปุ่มเริ่มบทสนทนาใหม่
- **CLI:** ใช้คำสั่งชุดเดียวกันผ่าน Terminal และพิมพ์ `/help` เพื่อดูคำสั่งทั้งหมด
- `/remember`, `/memories` และ `/forget` พร้อมการอนุมัติ ใช้งานได้แม้ยังไม่ได้ตั้ง API Key

## จุดเด่นของโปรเจกต์

- **Human-in-the-loop:** ผู้ใช้เป็นผู้ตัดสินใจขั้นสุดท้าย การลบ Memory และการบันทึกที่ AI เสนอต้องผ่านการอนุมัติเสมอ
- **ข้อความจาก AI เป็นแค่ข้อมูล ไม่ใช่คำสั่ง:** คำตอบของ AI ไม่ถูกนำไปรันเป็นคำสั่ง
  และหน้าเว็บแสดงข้อความจาก AI เป็นข้อความธรรมดา เพื่อกันลิงก์หรือรูปที่แฝงมาส่งข้อมูลออกไป
- **Privacy:** Memory เก็บในเครื่อง และไม่บันทึกประวัติแชตลงไฟล์
  ส่วนที่ต้องส่งให้ OpenAI เพื่อสร้างคำตอบ ได้แก่ ข้อความแชต ประวัติล่าสุด Memory ที่เกี่ยวข้อง
  วันเวลา และสรุปงานล่าสุด ทุกคำขอตั้งค่าไม่ให้ OpenAI เก็บผลลัพธ์ไว้เรียกดูภายหลัง
  (นโยบายการเก็บข้อมูลของ OpenAI เองยังมีผลตามปกติ) และมี Demo Mode ที่แยกจากข้อมูลจริง
- **เครื่องมือที่ปลอดภัยโดยการออกแบบ:** Tool Calling ใช้ได้เฉพาะเครื่องมือคำนวณที่อนุญาตไว้
  ตรวจข้อมูลนำเข้าอย่างเข้มงวด และจำกัดขนาดการคำนวณ
- **ควบคุมการใช้ API:** เห็นจำนวนการเรียกใช้และ Token ได้ตลอด และมีเพดานต่อ Session
- **ออกแบบให้เข้าใจง่ายและตรวจสอบได้:** Workflow ทำงานเป็นลำดับชัดเจนด้วยโค้ด Python ธรรมดา
  ไม่พึ่ง Agent Framework และทุกขั้นตอนมีผลลัพธ์ให้ผู้ใช้เห็น
- **ซื่อตรงต่อข้อจำกัด:** ระบบบอกตรง ๆ ว่าอะไรรับประกันได้และอะไรไม่ได้
  เช่น เพดานไม่ใช่เพดานค่าใช้จ่าย และการกรองข้อมูลไม่ครอบคลุมทุกกรณี
